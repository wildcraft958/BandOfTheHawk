# One exact set of versions, verified end to end on 31 Aug 2026.
#
# This file is NOT the dependency contract. pyproject.toml is: it carries lower
# bounds, which is what you depend on. This file exists to reproduce a run, and
# every version below was installed together into a clean virtual environment on
# CPython 3.14.7 (macOS, arm64), checked with `pip check`, and used to run the
# full test suite and the quick pipeline profile.
#
# ---------------------------------------------------------------------------
# INSTALL
#
#   python3 -m venv .venv && source .venv/bin/activate
#   pip install --upgrade pip
#   pip install -r requirements.txt
#   pip install -e .
#
# For a CUDA machine, install torch from the CUDA index FIRST, or pip resolves
# the CPU build off PyPI:
#
#   pip install torch==2.13.0 --index-url https://download.pytorch.org/whl/cu130
#   pip install -r requirements.txt
#
# Verify the GPU is visible:
#   python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
#
# Then:
#   CUDA_VISIBLE_DEVICES=0 python main.py --profile server
#
# Where the GPU is actually used: the generation and embedding models run once,
# in the `text` stage, and their output is cached into the pool. The
# reinforcement-learning networks are small multilayer perceptrons and the
# defender is gradient-boosted trees, so the remaining stages are bound by the
# simulation loop rather than by the device.
#
# On macOS, torch and xgboost each bring their own libomp and loading both in
# one process segfaults. tests/conftest.py detects this and names the fix.
# ---------------------------------------------------------------------------
